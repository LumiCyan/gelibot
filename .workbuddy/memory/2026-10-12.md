## QQ ↔ Minecraft 桥接桌面端（Electron）搭建

**目标**：用 SnowLuma（OneBot v11）接收 QQ 群/私聊消息，经权限判定后通过 RCON 向 MC Java 服务器投递指令，管理 QQ↔玩家ID 绑定。Windows 桌面 GUI。

**技术选型**

- Electron + TypeScript（主进程）+ React 18（渲染进程）
- 渲染进程用 esbuild 打包（注意：`npm install` 时 esbuild postinstall 会报 EBUSY，  
  解法是 `--ignore-scripts` 安装，再用 esbuild 的 JS API 调用，绕过 wrapper 版本探测）
- Electron 二进制需手动跑 `node node_modules/electron/install.js` 下载
- RCON 自写 `net.Socket` 实现，未用第三方库
- 依赖：ws、react、react-dom；devDeps：electron、esbuild、typescript

**项目结构**

```
src/shared/    types.ts（全部数据模型）、defaults.ts（默认配置与指令表）
src/main/      store.ts（JSON 持久化）、rcon.ts、onebot.ts、binding.ts、router.ts、main.ts
src/preload/   preload.ts（contextBridge 暴露白名单 IPC）
src/renderer/  App.tsx + pages/（6 个页面）
```

**安全模型（核心设计，务必保持）**

1. 聊天源白名单：非白名单群/私聊直接忽略（管理员豁免）
2. 指令模板化：`whitelist add {arg0}`，玩家输入只作参数代入，绝不拼接任意命令
3. 参数强校验：`^[A-Za-z0-9_]{3,16}$`（与 MC 用户名规则一致）
4. 换行注入防护：RCON 层剥离 `\r\n\0`
5. 限流：同用户冷却时间可配
6. 全量审计：每条投递的 RCON 命令落库

**绑定约束**：单 QQ 最大绑定数可配；玩家 ID 全局唯一防冒用；自助绑定可开关。

**验证结果**：14 项绑定/存储冒烟测试 + 7 项 RCON 协议测试（含 mock 服务端）

- 20 项权限路由测试，全部通过。注入尝试 `../../etc`、`Steve;stop`、`rm -rf`  
  均产生 0 次 RCON 调用。

**运行实测（2026-10-12 补充）**

- 环境坑：当前沙箱设置了 `ELECTRON_RUN_AS_NODE=1`，会让 Electron 退化为纯 Node 模式，  
  `require('electron')` 拿不到 app API，报 `Cannot read properties of undefined (reading 'whenReady')`。  
  启动命令必须 `env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe .`
- 窗口渲染后主进程会向已销毁的 render frame 推状态，报 `Render frame was disposed`。  
  已在 `broadcastStatus` 加 `isDestroyed()/isCrashed()` 双重校验 + try/catch，  
  并把首次连接延迟到 `did-finish-load`。
- `Store` 构造函数补了首次运行落盘逻辑，`data/config.json` 会被自动创建。
- 6 个页面全部截图核验通过，截图归档在 `docs/screenshots/`。
- 新增 `run.cmd`：Windows 双击即可「构建 + 启动」，内置清除 `ELECTRON_RUN_AS_NODE`。
- 临时探针脚本（`_probe.cjs` / `_shots*.cjs`）已删除。

## 绑定功能改造：对齐 EasyBot（2026-10-12 下午）

**需求**：参照 <https://docs.inectar.cn/docs/easybot/features/bind/> 做一样的绑定方式。

**EasyBot 的绑定模型（调研结论）**

- 两种模式：**双向验证模式**（服务器内 `/easybot bind` 取验证码 → 群内「绑定 + 验证码」）  
  和**社交平台信任模式**（群内直接「绑定 + 游戏ID」）
- 强制绑定：列表中的服务器必须绑定才能进；解绑即踢出
- 退群自动解绑（核心事件 → 退群事件）
- 群名片改名：绑定后改名 / 发消息时更新 / 不改
- 服务端插件侧配置项：`command.allow_bind`、`message.bind_start/bind_success/bind_fail`  
  （占位符 `#code` `#time` `#account` `#name` `#why`）、`event.bind_success` 控制台命令

**踩坑**

- 路由测试里连续发消息会被默认 `rateLimitMs: 1500` 拦掉，断言全变「操作太频繁」。  
  解法：测试 harness 里 `rateLimitMs = 0`，限流单独一条用例覆盖。
- 截图脚本是独立 Electron 进程，没有主进程 IPC，页面白屏。  
  解法：脚本内注册最小 mock handler（config:get / status:get / binding:list / bindcode:list）。
- 非 `--dev` 模式的配置写到 `%APPDATA%/qq-mc-bridge/data/`，不是项目内 `data/`。
