### 关键技术障碍与解决

1. **GitHub 完全不可达（`HTTP 000`，空响应）—— 根因是 Windows schannel 吊销检查失败**

   ```
   schannel: next InitializeSecurityContext failed:
   CRYPT_E_NO_REVOCATION_CHECK (0x80092012) - 吊销服务器无法验证
   ```

   代理隧道本身是通的（`CONNECT ... 200 Connection Established`），
   卡在 TLS 握手的证书吊销查询上。

   - `curl` 侧解决：加 `--ssl-no-revoke`
   - `git` 侧解决：`git config http.sslBackend schannel` +
     `git config http.schannelCheckRevoke false`
     （注意：只传 `-c http.schannelCheckRevoke=false` 不够，需持久写入本地仓库配置）

   这个坑值得记住：以后在本机访问任何 HTTPS 服务报 `HTTP 000` 且响应体为空，
   先怀疑 `CRYPT_E_NO_REVOCATION_CHECK`，而不是「网络不通」。

2. **Node 在 Git Bash 下把 `/tmp` 解析为 `D:\tmp`** ——
   `fs.writeFileSync("/tmp/x.json")` 报 `ENOENT: no such file or directory, open 'D:\tmp\x.json'`。
   解决：临时文件一律放项目内的 `.stage/`（已在 .gitignore 中）。

3. **`license_template: mit` 会让远程多出一个 Initial commit**，
   与本地首次提交形成 `add/add` 冲突。
   解决：`git merge origin/main --allow-unrelated-histories` +
   `git checkout --ours LICENSE` 保留本地带中文说明的许可文件。

### 图标来源

用户提供 `D:\桌面\图片\2091E340CACFB91CF346EEBFDCB92645.jpg`，
**其实是鸽子，也就是 GeLi = 鸽力 的由来**（此前误称鸭子，已全部改名 pigeon）。

- `scripts/make-icon.py` → `build/icon.ico`（7 档：16/24/32/48/64/128/256）
- `scripts/make-ui-assets.py` → `src/renderer/assets/`（brand-64/brand-32/window-256）
- 覆盖三处：exe 文件图标、任务栏/窗口图标、界面左上角品牌方块

### 图标生成的三个硬坑

1. **源图是 APNG**：魔数 `\x89PNG` 但带 `acTL`/`fcTL` chunk，扩展名却写 `.jpg`。
   通用图片工具拒解析 → 脚本内手写 PNG 解滤波（filter 0/1/2/3/4）。
2. **背景是纯水平渐变**（左 `#96ff8f` → 右 `#8dfffa`），不是对角渐变。
   四角采样验证：左上=左下、右上=右下、上下中点一致 → v 不参与。
   早期按对角建模会渲染出明显色带断层。
3. **不能对掩码做闭运算**：眼睛是「背景色镂空」，源图约 100px，缩到 32px 只剩 ~2.5px，
   闭运算半径 ≥2 直接填平 → 鸽子变成没眼睛的黑团。
   小尺寸改用 `flatten_ink`（把亮且低饱和的前景像素压黑）+ `trim_speedlines`
   （≤32px 裁掉 x>845 的速度线伸出段）。

### exe 图标未写入 —— 两层根因（v1.15.0 也中招）

**根因一**：`electron-builder.config.js` 里 `signAndEditExecutable: false`。
它在 `app-builder-lib/out/winPackager.js` 的 `signApp()` 里是**一票否决**：

```js
async signApp(packContext, isAsar) {
  if (this.platformSpecificBuildOptions.signAndEditExecutable === false) {
    return false;                      // 直接返回，图标永不写入
  }
  ...
  await this.signAndEditResources(...)  // 写图标发生在这里
}
```

**根因二**：改回 `true` 后卡在解压 `winCodeSign`。归档含两条 macOS 符号链接
（`darwin/10.12/lib/libcrypto.dylib`、`libssl.dylib`），普通 Windows 账户无
`SeCreateSymbolicLinkPrivilege`：

```
ERROR: Cannot create symbolic link : 客户端没有所需的特权
7za 退出码 = 2  →  app-builder 重试 3 次后放弃，同样到不了写图标那步
```

**最终解法（`scripts/build-release.mjs`）**：二进制等长补丁。
`app-builder.exe` 里 `-snld` 字面量**只出现一次**（偏移 **9019367**），
而 7-Zip 的 `-snl-`（不还原符号链接）恰好也是 **5 个 ASCII 字节** → 原地替换，
再通过官方环境变量 `CUSTOM_APP_BUILDER_PATH` 指向补丁副本。
不动 `node_modules` 原文件，`npm install` 后依然有效。

> 试过但**失败**的方案：写 `.cmd` shim 冒充 `7za`（配 `USE_SYSTEM_7ZA=true`）。
> 原因：Go 的 `exec.Command("7za")` 在 Windows 上**无法直接执行 `.cmd`**
> （`LookPath` 能找到，但 `CreateProcess` 需要 shell）。必须是真 `.exe`。

### 两个值得复用的排查经验

1. **PE 资源目录三级结构**：type → name(资源ID) → language → data entry。
   子目录与叶子偏移**相对于资源段基址**，不是 RVA。
   第三级的 ID 是**语言 ID（1033）**，不是资源 ID —— 曾因此把 `find_resource`
   的返回值搞错，导致逐档比对全部误报 FAIL。
2. **exe 里 128/256 大图标存成 PNG**（而 `build/icon.ico` 存 DIB），
   字节不同但图像一致。校验脚本要能识别 `\x89PNG` 头并解 PNG 再比像素。
