### 本轮验证结论（全部实测通过）

1. **正式图标可直接复用现有产物**：`src/renderer/assets/window-256.png`
   （8.4 KB，与 `build/icon-preview-256.png` 同源）。转 base64 后 11.2 KB，
   内嵌进卡片 HTML 零负担 —— 不需要新增图标导出脚本。46px 显示下速度线清晰。
2. **QQ 头像走 `net.fetch` 完全可用**（Electron 33.2.1）。这是关键：
   **本机 Node 的 TLS 会被证书吊销检查卡住（`CRYPT_E_NO_REVOCATION_CHECK`），
   但 Electron 的 `net.fetch` 走 Chromium 网络栈，不吃这个坑。**
   卡片取头像必须用 `net.fetch`，不要用 `require('https')` 或 Node 的 `fetch`。
   - 6 张并发拉取耗时 **440ms**，失败 0
   - 接口：`https://q1.qlogo.cn/g?b=qq&nk=<QQ>&s=100`，200 + `image/jpeg`/`image/png`
   - 返回格式**不固定**（jpeg / png 都有）→ 必须按魔数嗅探 MIME，不能写死 image/jpeg
3. **窗口高度自适应可用**：活内容（玩家数变化）先 `executeJavaScript` 量
   `.card` 的 `getBoundingClientRect().height`，再 `setContentSize` 后截图。
   实测 482 CSS px → 输出 750x604（125% 缩放，自带高清）。
4. 四角 A=0 完全透明，群内显示无黑角。单次渲染 **1.5s**，PNG 65 KB。

## 数据目录「换版本要重新配置」问题排查（结论）

用户反馈：换版本后配置不互通，要重新配。**已完整定位机制。**

### 真相：数据目录由「产品名」决定，与版本号无关

`main.ts:40` → `getDataDir()` → `path.join(app.getPath('userData'), 'data')`，
而 Electron 的 `userData = %APPDATA%/<app.getName()>`，`getName()` 取
`app.asar` 内 `package.json` 的 **productName**（靠 `electron-builder.config.js`
的 `extraMetadata.productName: 'GeLi Bot'` 写进去）。

本机实证 —— `%APPDATA%` 下三个目录，就是名字变过三次的痕迹：

| 目录 | 对应版本 | 内容 |
| ---- | ---- | ---- |
| `GeLiCraft` | v1.14.x（productName 叫 GeLiCraft） | 默认配置（127.0.0.1:25575，无密码） |
| `gelibot` | v1.15.0（productName 没写进 asar，退化成小写 name） | 同上，默认配置 |
| `GeLi Bot` | v1.15.1 起（含 v1.16.0） | **用户的真实配置**（RCON 真实地址 + 白名单群 337012223） |

**所以：v1.15.1 → v1.16.0 → 未来版本，数据是共享的，升级不会丢配置。**
`migrateLegacyData()`（v1.15.0 引入，三个版本都在）还会自动把旧目录搬过来。

### 但它是「隐形脆弱」的

任何一次产品改名、或打包时漏掉 `extraMetadata.productName`（v1.15.0 就是这么中招的），
就会**静默**生成一个全新的空目录，用户看到的是「全新软件」。而且：

- 没有导入/导出，**没有任何备份手段**（删掉 `%APPDATA%\GeLi Bot` 就彻底没了）
- 现有迁移只认 2 个硬编码名字，且只在「新目录不存在」时执行，且**不告诉用户它做了什么**

### 关键可行性事实（已读 electron-builder 源码确认）

`node_modules/app-builder-lib/templates/nsis/portable.nsi:77-79` 给便携版注入了：

```
PORTABLE_EXECUTABLE_DIR          = $EXEDIR   ← 用户放 exe 的那个文件夹
PORTABLE_EXECUTABLE_FILE         = $EXEPATH
PORTABLE_EXECUTABLE_APP_FILENAME = ${APP_FILENAME}
```

**源码里从未用过这三个变量。** 注意：便携版会把应用解到 `%TEMP%\GeLiBot` 运行，
所以 `app.getPath('exe')` 是临时目录 —— 要找「exe 原来的位置」**必须**读
`PORTABLE_EXECUTABLE_DIR`，不能靠 exe 路径。这是「绿色版数据跟随 exe」方案的地基。

### 已给出的三个方案（等用户拍板）

- **A. 数据目录跟随 exe（绿色版模式）**：启动时若 `<PORTABLE_EXECUTABLE_DIR>/data/config.json`
  存在则优先用它，否则回退 `%APPDATA%\GeLi Bot\data`。换版本/换电脑只需拷目录。
- **B. 配置导入 / 导出**：导出单个 JSON（config + bindings），跨改名/跨机通用，兼作备份。
- **C. 加固**：迁移从硬编码名单扩展为「扫描 `%APPDATA%\*\data\config.json`、
  按内容特征识别、取最新、并告知用户」；界面显示当前数据目录 + 打开目录按钮；
  可选 `--data-dir=<path>` 参数。

推荐 A + B，C 作加固。**待用户选择后开工。**

### 关键决策与坑

1. **必须读 `PORTABLE_EXECUTABLE_DIR`**，不能用 `app.getPath('exe')` ——
   便携版会把自己解压到 `%TEMP%\GeLiBot` 再运行，exe 路径是临时目录。
   （已在 `portable.nsi:77` 确认变量由打包器注入。）
2. **exe 旁 data 不可写时回退**到 `%APPDATA%/GeLi Bot/data` 并给出 warning。
   若硬写会静默失败，等于配置丢失 —— 这是本功能里最需要防的失败模式。
3. **导出默认脱敏**（RCON 密码 ×2 + OneBot AccessToken），勾选才带上。
4. **导入是合并而非覆盖**：
   - 脱敏文件不覆盖本机已有密码（否则「导一次配置把服务器连不上」）
   - 绑定按 `qq + playerId.toLowerCase()` 去重追加
   - 配置走 `mergeConfigWithDefaults`，因此**从旧版本导出的配置也能自动补齐新字段**
5. 导入除了接受本程序的导出包，**也接受裸 `data/config.json`**（用户最常见的操作）。
6. `config:reset` 里原先重复了一份「切换组件」的代码，已统一到 `applyConfig()`，
   以后新增组件不会漏掉恢复默认这条路径。
