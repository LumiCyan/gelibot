## 本版变更

### 全新应用图标：鸽子

全站图标换成鸽子剪影——取自 **GeLi = 鸽力** 的谐音梗，左侧是带尖喙的鸽子头，右侧三道白色速度线。

新图标覆盖了三个位置：

| 位置 | 说明 |
| ---- | ---- |
| **exe 文件图标** | 资源管理器、桌面快捷方式上显示的那一个 |
| **任务栏 / 窗口图标** | 运行时窗口标题栏与任务栏按钮 |
| **界面左上角** | 顶栏 "GeLi Bot" 字样左侧的品牌方块 |

配色沿用原图的**绿→青水平渐变**底，主体为黑色鸽子。

#### 小尺寸单独做了精简

16 / 24 / 32px 下的图标**不是简单缩放**。原图缩到这么小时，三道白色速度线会糊成一团灰点，既看不清又脏。所以按尺寸分档处理：

| 尺寸 | 处理 |
| ---- | ---- |
| 48px 及以上 | 完整还原（含速度线与眼睛镂空） |
| 32px | 压掉速度线，保留眼睛镂空 |
| 16 / 24px | 裁掉右侧速度线伸出段，只留干净的鸽子剪影 |

每一档都保留了眼睛，因为那是辨识度的关键。

### 实现说明（给要改图标的人）

图标由 `scripts/make-icon.py` 从用户提供的源图直接生成，**不依赖 Pillow**，纯手写 PNG 解码与 ICO 字节流：

```bash
python scripts/make-icon.py        # 生成 build/icon.ico（7 档尺寸）
python scripts/make-ui-assets.py   # 生成界面用的 brand-64.png / window-256.png
```

几个踩过的坑记在这里：

- **源图其实是动画 PNG**（带 `acTL` / `fcTL` chunk），扩展名却写着 `.jpg`。
  通用图片工具会拒解析，脚本里手工做了 PNG 解滤波还原。
- **背景是纯水平渐变**，不是对角渐变。早期误判成对角，渲染出来有一条明显的色带断层。
  按四角采样确认：左上/左下同为 `#96ff8f`，右上/右下同为 `#8dfffa`，只有水平分量。
- **不能对掩码做闭运算**。鸽子眼睛是"背景色镂空"，缩到 32px 只剩约 2.5px，
  闭运算半径 ≥2 就会把它整个填平，鸽子变成没眼睛的黑团。

#### 另一个坑：exe 图标差点没写进去

图标生成好了、`build/icon.ico` 也对，但打出来的 exe 顶着 Electron 默认的电子轨道图标。
根因有两层：

1. `electron-builder.config.js` 里早期为绕过受限网络设了 `signAndEditExecutable: false`。
   看 `app-builder-lib/out/winPackager.js` 的 `signApp()` 会发现它是一票否决：
   直接 `return false`，后面的 `signAndEditResources()`（写图标那步）根本不执行。

2. 改回 `true` 后又卡在解压 `winCodeSign` 工具链：归档里含两条 macOS 符号链接
   （`darwin/10.12/lib/libcrypto.dylib` 等），普通 Windows 账户没有创建符号链接的权限，
   `7za` 报「客户端没有所需的特权」并以退出码 2 结束；app-builder 视非 0 为失败，
   重试 3 次后放弃 —— 而它发生在写图标**之前**，等于白改。

最终解法见 `scripts/build-release.mjs`：`app-builder.exe` 里 `-snld` 这个字面量只出现一次，
而 7-Zip 的 `-snl-`（不还原符号链接）恰好也是 5 个 ASCII 字节，于是**原地等长替换**，
再通过官方的 `CUSTOM_APP_BUILDER_PATH` 指向打补丁后的副本，不动 `node_modules` 原文件。
被跳过的两条 `.dylib` 只是 macOS 构建用的快捷方式，Windows 打包完全用不到。

打包用：

```bash
npm run dist          # 等价于 node scripts/build-release.mjs
```

## 这一版包含的功能

- **内置 SnowLuma**：一键启动器，自动开后台、直取登录凭据、数据目录分离、随程序退出
- **账号绑定双模式**：双向验证（游戏内取码 + 群内提交）／社交平台信任（群里直接绑）
- **验证码**：位数、字符集（易混淆字符已剔除）、有效期可配，一次性语义，重取作废旧码
- **强制绑定**：未绑定进服踢出（RCON kick）
- **退群自动解绑**、**绑定后改群名片**（三种策略）
- **可自定义消息模板**（6 个文案，支持 `#code` `#time` `#account` `#player` `#why` 占位符）
- **权限路由**：群 / 私聊 / 管理员三类白名单，9 条内置指令
- **安全**：指令走模板 + 参数白名单校验（`^[A-Za-z0-9_]{3,16}$`），杜绝拼接注入；同用户限流
- **全量审计日志**：每条指令执行与拦截都有记录
- **6 个功能页面**的图形界面

## 快速开始

1. 双击 `GeLi Bot v1.15.1.exe`（首次启动需 3–10 秒解包）
2. 「连接设置」页 → 点 **启动 SnowLuma** → 自动打开后台 `http://127.0.0.1:5099`
3. 后台里扫码登录 QQ
4. 后台 → **节点配置 → WS 服务端**，复制 **accessToken**
5. 回到本程序，填入 `ws://127.0.0.1:3001` 和刚复制的 Token，**保存配置**
6. 顶栏「QQ」变绿即通

> **最容易踩的坑**：Token 必须与服务端完全一致。服务端设了 Token 而这边留空，握手会直接 401。
> 界面上的固定提示与错误横幅都会提醒这一点。

## 已知限制

- **服务端插件桥尚未实现**：玩家在游戏内打 `/easybot bind` 目前无法触发取码。
  验证码的签发、RCON 播报、校验链路都已完整，缺的只是「服务端 → 本程序」这一段触发。
  现阶段可用两种替代：① 在绑定页用「签发验证码」代发；② 改用社交平台信任模式。

- **RCON 密码明文存储**在 `config.json`，请确保该目录权限可控。
  RCON 走明文 TCP，务必只在 `127.0.0.1` 监听，不要暴露到公网。

- **仅 portable 单文件版**，暂无安装版（无开始菜单快捷方式与卸载项）。

本程序内置的 **SnowLuma** 是源码可见的**非商业**许可项目，核心 native 组件闭源。

- 自己用、团队内部用：没问题
